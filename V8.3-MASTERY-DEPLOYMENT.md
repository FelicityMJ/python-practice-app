## Firebase rule deployment
The included rule file permits the v8.3 `masteryPlacement` preference. If Firebase CLI is configured for the project, deploy the Firestore rules using your normal Firebase deployment workflow. Do not deploy an older saved copy of `firestore.rules` over this one afterwards.

## Safe migration behaviour
There is no destructive data migration. v8.3 reads existing progress and treats old completed work without a mastery version as secure legacy evidence. New work then accumulates v8.3 mastery fields normally.

## Daily Mastery logic
The daily plan uses:
- older retained material;
- reviews that are due now;
- skills with weak recent evidence;
- a recommended new, strengthening or prerequisite-repair activity.

The diagnostic placement lets the mastery route bypass earlier units without deleting or hiding them from Full Course.

## Mastery meaning
- **Learning**: started but not secure.
- **Completed · developing**: the activity has been finished but does not yet meet mastery evidence.
- **Mastered**: secure evidence has been demonstrated.
- **Retained**: mastery has survived delayed retrieval.
- **Needs repair**: repeated recent failure indicates a prerequisite or previously learned skill needs strengthening.

For machine-marked practice, clean first-pass success or repeated correct evidence can establish mastery. Six-practice fluency sets use the stricter set rule: all six correct eventually, at least five first-pass correct, and no more than one hint across the set.

Self-reviewed extended exam responses cannot be objectively machine-marked, so completing the required self-review counts as secure enough to advance without being used as machine-verified delayed-retention evidence.
